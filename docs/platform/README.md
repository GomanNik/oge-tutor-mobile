## Термины

| Термин | Значение |
|---|---|
| Пользователь | Одна учётная запись и способ входа; может иметь несколько назначений ролей. |
| Рабочее пространство | Граница данных и административного управления школы, команды или отдельного преподавателя. |
| Предмет | Общая дисциплина, например математика; сам по себе не задаёт экзамен и правила оценки. |
| Программа | Экзамен + предмет + вариант/уровень, например ЕГЭ/математика/профиль. |
| Версия программы | Опубликованный каталог заданий и правила оценки конкретного периода; после использования неизменяем. |
| Курс | Проводимое обучение по одной версии программы в рабочем пространстве. Имеет формат по умолчанию, преподавателей и участников. |
| Поток | Необязательный административный состав учеников, который можно использовать при наборе на несколько курсов разных предметов. Сам по себе не предоставляет доступ к курсам. |
| Зачисление | Участие конкретного ученика в конкретном курсе в определённый период. |
| Занятие | Запланированное или проведённое событие курса с явно зафиксированными преподавателями и участниками. |
| Назначение | Выданная в курсе работа; получатели и их результаты учитываются отдельно. |
| Доказательство прогресса | Запись о проверке, занятии или ручной оценке с автором, временем и контекстом; источник производной сводки. |

Слова «группа» и «индивидуальное обучение» обозначают **формат курса по умолчанию**, а не два несовместимых типа аккаунтов или две независимые реализации. В групповом курсе допустима консультация для части участников. Один ученик вправе иметь несколько курсов и преподавателей, в том числе по одной программе.

## Зафиксированные проектные принципы

- Предметный каталог отделён от людей и курсов. Номер задания имеет смысл только внутри версии программы; внутренние связи используют стабильный ID задания.
- Доступ предоставляют роль в рабочем пространстве и конкретное участие в курсе, а не только глобальная роль или знание ID ресурса.
- У занятия и назначения есть собственные списки участников/получателей. Изменение состава курса не переписывает прошедшие события.
- Прогресс ученика по курсу и его сводка по программе — разные представления. Исходные оценки преподавателей не затираются агрегатом.
- Архивирование и завершение связей — штатные действия. Физическое удаление использованных учебных данных не является обычным пользовательским действием.
- Сначала корректность доступа, истории и календаря; автоматизация, аналитика и новые каналы доставки добавляются поверх них.

## Открытые решения до реализации

| Вопрос | Рекомендуемый старт | Что меняется при ином выборе |
|---|---|---|
| Кто управляет глобальным каталогом? | Назначенный администратор каталога; администратор пространства может включать версии и создавать локальные черновики. | Потребуются правила публикации и доверия к пользовательским программам. |
| Кто приглашает ученика? | Администратор; преподавателю можно выдать отдельное право приглашать в свои курсы. | Меняется процесс согласования и защиты от дублирования аккаунтов. |
| Можно ли состоять у двух преподавателей по одной программе? | Да; прогресс ведётся отдельно по зачислениям. | При запрете требуется глобальное ограничение уникальности. |
| Как использовать поток? | Только как удобный шаблон набора; зачисления в курсы подтверждаются явно. | Автоматическая синхронизация состава создаёт сложные последствия для доступа и истории. |
| Кто видит оценки другого преподавателя? | Ученик видит свои опубликованные результаты; преподаватель — свои курсы; межкурсовая сводка без чужих личных заметок. | Потребуются отдельные права и политика согласия на обмен. |
| Можно ли обойти конфликт расписания? | В блоке 4 обход запрещён всем; продуктовая политика исключений не утверждена. | Если разрешить администратору обход, нужны причина, аудит и уведомление всех затронутых людей. |
| Нужны ли соведущие и замены сразу? | Схему и права заложить; UI внедрять после базовых групп. | Иначе позже придётся менять владельца занятий и доступа. |
| Нужны ли внешние опекуны, платежи и видеосвязь? | Не входят в первый выпуск; предусмотрены интеграционные границы. | Расширяют модель согласий, финансов и коммуникаций. |
