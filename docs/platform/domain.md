# Целевая доменная модель

Статус: проект, **не Prisma-схема работающего приложения**. Названия ниже обозначают концепции; финальные имена таблиц и DTO утверждаются при реализации. Термины — в [индексе](README.md), правила доступа — в [отдельном документе](access.md).

## Карта связей

```text
User 1──* WorkspaceMembership *──1 Workspace
User 1──* CatalogGrant
Subject 1──* ExamProgram 1──* ProgramVersion 1──* TaskDefinition
Workspace 1──* Course *──1 ProgramVersion
Course 1──* CourseTeacher *──1 TeacherProfile/User
Course 1──* Enrollment *──1 StudentProfile/User
Workspace 1──* Cohort 1──* CohortMember *──1 StudentProfile/User
Course 1──* Lesson 1──* LessonParticipant *──1 Enrollment
Lesson 1──* LessonTeacher *──1 CourseTeacher
Course 1──* Assignment 1──* AssignmentRecipient *──1 Enrollment
AssignmentRecipient 1──* Submission
Enrollment 1──* ProgressEvent *──0..1 TaskDefinition
ProgramVersion/Course/Lesson/Assignment ──* MaterialLink *──1 FileResource
User 1──* Notification; Workspace 1──* AuditEvent
```

`Cohort` — шаблон состава нескольких курсов, не замена `Enrollment`. `LessonParticipant` и `AssignmentRecipient` — самостоятельные исторические записи. Отсутствие ученика в текущем составе курса не стирает факт его участия в прошлом.

## Идентичность и пространство

| Сущность | Существенные поля и ограничения |
|---|---|
| `User` | Стабильный ID, нормализованный уникальный email, пароль/провайдер входа, статус, версия сессий. Профиль человека отделён от ролей. Смена email подтверждается; адрес не используется как внешний ключ истории. |
| `Workspace` | ID, название, статус, настройки приглашений/видимости/часового пояса. Все учебные данные имеют одно пространство. |
| `WorkspaceMembership` | `workspaceId + userId`, набор назначений или отдельные строки ролей, статус и даты. Уникальность активного назначения по паре/роли. Пользователь может состоять в нескольких пространствах; контекст пространства выбирается явно. |
| `TeacherProfile`, `StudentProfile` | Личные данные и настройки, связанные с `User` один-к-одному; не содержат «единственного» преподавателя или предмет. Учебные цели и приватные заметки конкретного преподавателя живут в `Enrollment`. |
| `CatalogGrant` | Право управлять общим каталогом независимо от учебных ролей пространства. Без него администратор пространства не переписывает глобальные экзаменационные версии. |

Один и тот же ученик, приглашённый в другой курс или пространство, получает новую связь/зачисление, а не копию `User`. Поиск совпадений по email не должен раскрывать чужое пространство: приглашение существующего аккаунта завершается подтверждением владельца аккаунта либо документированным административным процессом.

## Каталог и версия экзамена

| Сущность | Существенные поля и ограничения |
|---|---|
| `Subject` | Стабильный код и имя; глобальный или локальный справочник с владельцем. Архивирование не меняет существующие курсы. |
| `ExamProgram` | Тип экзамена, `subjectId`, вариант/уровень и стабильный код. ОГЭ/математика, ЕГЭ/математика/база и ЕГЭ/математика/профиль — разные программы. |
| `ProgramVersion` | `programId`, учебный/экзаменационный период, номер ревизии, статус черновик/опубликована/архив, дата публикации, ссылка на источник и политика оценки. Пара `(programId, period, revision)` уникальна. |
| `TaskDefinition` | Стабильный ID внутри версии, видимый номер/код, название, темы, порядок, тип, максимальный балл и критерии. Уникальный видимый код **только внутри версии**. Не предполагается диапазон 1–25. |
| `TaskMapping` | Необязательная явная связь эквивалентных заданий между версиями для переноса аналитики. Без подтверждённой связи автоматическое сравнение по одинаковому номеру запрещено. |
| `ScoringRule` | Версионируемый идентификатор правила, параметры и применимость; результат содержит ID правила и исходные данные расчёта. Отсутствие подтверждённого правила означает отсутствие прогноза, а не фиктивный ноль. |

После первого использования опубликованной версии в курсе её задания и правила **не меняются на месте**. Исправление создаёт новую ревизию и явный процесс перевода будущих курсов; исторические занятия, работы и оценки продолжают ссылаться на прежнюю версию. Названия для UI могут меняться отдельно от расчётных параметров только при наличии безопасного механизма исправлений и аудита.

## Курсы, люди и календарь

| Сущность | Существенные поля и ограничения |
|---|---|
| `Course` | `workspaceId`, `programVersionId`, название, формат по умолчанию (`individual`/`group`), вместимость, период, статус, настройки набора, версия записи. Только одна версия программы на курс. |
| `CourseTeacher` | `courseId + teacherId`, роль (`lead`/`assistant`/`substitute`), интервал назначения, полномочия и статус. Не менее одного активного ведущего у действующего курса; назначение в курсе требует доступа к программе. |
| `Enrollment` | `courseId + studentId`, интервал, статус, инициатор, индивидуальные цель/условия/заметка, версия записи. Не более одного пересекающегося активного зачисления одного ученика в **том же курсе**; в разных курсах одна программа разрешена. |
| `CourseWaitlist` | Отдельная очередь заявок без доступа к материалам/занятиям. Освобождение места не означает автоматическое зачисление без принятой политики. |
| `Cohort`, `CohortMember` | Необязательный административный поток и его состав. Массовое зачисление в курсы создаёт отдельные `Enrollment` после проверки вместимости/прав. |
| `Lesson` | `courseId`, начало/конец UTC, зона отображения, формат, место/ссылка, статус, источник, версия записи, `recurrenceId` при необходимости. Интервал времени полуоткрытый `[startAt,endAt)`. |
| `LessonTeacher` | Снимок назначенных на урок преподавателей; возможна замена без изменения владельца курса. |
| `LessonParticipant` | Снимок приглашённого `Enrollment`, статус ответа и посещаемость (`unknown`/`present`/`absent`/`excused`), время и автор отметки. Одна запись на зачисление в уроке. |
| `RecurrenceRule` | Правило локального времени, зоны, даты окончания и поколение созданных будущих уроков. Отдельные уроки и исключения имеют собственные ID; не хранится только «бесконечное правило». |

Формат курса — стартовое значение; для урока явно выбирают всех, часть или одного участника. Индивидуальный курс допускает одного активного ученика, групповой — до вместимости. Если нужна совместная встреча двух курсов/программ, это отдельная будущая модель; связывать один урок с двумя версиями программы без правил прогресса нельзя.

Проверка вместимости и временных конфликтов выполняется транзакционно. При одновременном зачислении последнее свободное место получает не более одного ученика. Для урока конфликтуют все приглашённые ученики и назначенные преподаватели **во всех их курсах**; отменённые события не блокируют время. Переходы через полночь и переходы часового пояса тестируются отдельно. Административное исключение хранит причину, пользователя и затронутых людей.

## Работы, прогресс и материалы

| Сущность | Существенные поля и ограничения |
|---|---|
| `Assignment` | `courseId`, возможно `lessonId`, тема/инструкция, ссылки на `TaskDefinition` версии курса, дата публикации, статус, общая дата сдачи и версия записи. Черновик не виден ученикам. |
| `AssignmentRecipient` | `assignmentId + enrollmentId`, персональный срок, статус, причина освобождения, опубликованные материалы и момент назначения. Получатели фиксируются при публикации; повторная публикация не дублирует строки. |
| `Submission` | Получатель, порядковый номер попытки, автор, время, файл/ответ, статус проверки. Попытка и оценка сохраняются после последующей доработки. |
| `Review` | Проверяющий, оценка по критериям версии программы, комментарий, состояние публикации и время. Исправление — новая ревизия/событие, не бесследная перезапись. |
| `ProgressEvent` | `enrollmentId`, `taskDefinitionId?`, источник (`lesson`, `submission`, `diagnostic`, `manual`), автор, оценка, видимость, ссылки на доказательство и время. История неизменяема; коррекция ссылается на отменяемое событие. |
| `ProgressProjection` | Производное последнее состояние по `(enrollmentId, taskDefinitionId)` с версией алгоритма и моментом пересчёта. Может быть восстановлено из событий. Межкурсовая сводка строится отдельно. |
| `Material`/`MaterialLink` | Файл, ссылка или библиотечный ресурс; владелец, версия программы/курс/задание, публикация, видимость и привязка к уроку/работе. Связи явные; доступ не выводится из одного совпавшего номера задания. |
| `FileResource` | Владелец/пространство, физический ключ, размер, определённый по содержимому тип, контрольная сумма, статус проверки и ссылки. Скачивание требует допустимой связи, а не только знания URL. |
| `Notification` | `recipientUserId`, тип события, контекст, статус, время, дедупликационный ключ; одна запись на получателя. |
| `AuditEvent` | Пространство, актор, действие, целевая сущность, безопасные старые/новые значения или описание изменения, причина, `requestId`, время; доступ ограничен. |

Прогноз результата — **производная, а не факт**. Алгоритм и его версия должны быть известны, применимы к этой версии программы и понятны пользователю. Нельзя усреднять результаты разных версий или преподавателей без отдельно утверждённого правила; в противном случае показываются раздельные данные и происхождение.

## Состояния и переходы

| Объект | Основной путь | Недопустимо без специального процесса |
|---|---|---|
| Программа | `draft → published → archived` | Править задания/оценивание опубликованной использованной версии. |
| Курс | `draft → active ↔ paused → completed → archived` | Активировать без ведущего/программы; архивировать с неразобранными будущими уроками и работами. |
| Зачисление | `invited → active ↔ paused → completed/withdrawn` | Получать доступ до активации; стереть участие после прошедших занятий. |
| Урок | `planned → rescheduled → completed` либо `planned/rescheduled → canceled` | Завершать до начала; менять участников завершённого урока без корректировки с аудитом. |
| Работа | `draft → published → closed → archived` | Менять смысл задания после сдач без новой ревизии. |
| Получатель ДЗ | `assigned → submitted → reviewed` либо `submitted → needs_revision → submitted`; возможен `exempt` | Делать результат одного ученика видимым остальной группе по умолчанию. |
| Материал | `draft → published → archived` | Сохранять публичную ссылку после отзыва доступа, если право больше не действует. |

Терминальные статусы не равны физическому удалению. Для ошибочного действия существует явная корректировка с автором и причиной.

## Инварианты БД и границы транзакций

- Внешние ключи учебных сущностей не могут указывать на другой `workspaceId`; для особо важных связей нужны составные ключи/ограничения или эквивалентная транзакционная проверка, а не надежда на UI.
- `Course.programVersionId` совпадает с версией каждого назначенного задания и используемой предметной аналитики. Видимые номера не служат ключами.
- Запись `LessonParticipant` относится к `Enrollment` того же курса; `AssignmentRecipient` — аналогично. Исторические строки не удаляются при завершении зачисления.
- Интервалы участников, преподавателей и курса покрывают время планируемого урока согласно явному правилу допуска. Незавершённая серия не создаёт бесконечное число строк.
- Уникальны `(lessonId,enrollmentId)`, `(assignmentId,enrollmentId)`, `(enrollmentId,taskDefinitionId)` у проекции; события прогресса не уникализируются по времени.
- Изменение состава, публикация работы, перенос занятия, проверка сдачи и добавление события прогресса фиксируются атомарно в БД; внешняя доставка уведомлений выполняется после фиксации.
- Обычные удаления `User`, `Course` и `ProgramVersion` не должны каскадом уничтожать доказательства обучения. Политика хранения и отдельное удаление персональных данных определяются перед запуском в производство.

## Миграция от текущей модели

Для каждой существующей пары преподаватель–ученик создаётся индивидуальный курс по импортированной версии ОГЭ/математика и зачисление. Исходные ID, времена, авторы и связи уроков/ДЗ/прогресса сохраняются через таблицу соответствий. Если у одного ученика несколько старых записей или данные не однозначны, миграция **останавливается с отчётом**, а не угадывает объединение. Подробный порядок — в [плане перехода](migration-and-acceptance.md).
