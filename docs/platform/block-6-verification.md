## Матрица приёмки

| Требование | Доказательство |
|---|---|
| Раздельный прогресс по курсам/версиям | E2E создаёт несколько курсов одного ученика; сводка не усредняет преподавателей, другая версия не объединяется по номеру задания. |
| Источники и неизменяемость | Проверка работы создаёт адресные факты; исправленная проверка связывает замены; урок сохраняет посещаемость без вымышленного освоения; БД запрещает UPDATE/DELETE истории. |
| Личные записи | Другой преподаватель, ученик и администратор не получают частную оценку. Перенесённые комментарии v1 сохраняются только в закрытом legacy-снимке. |
| Оценка, исправление, отзыв | E2E проверяет баллы/максимум, состояние, основание, часовой пояс, повтор ключа, конфликт тела, конкурирующие исправления, отзыв и rebuild. Браузер проверяет частную оценку и явную публикацию исправления. |
| Адресные уведомления | Повтор доменной команды не создаёт дубли; счётчик и read/read-all принадлежат получателю. Прямой чужой ID и отозванная связь не открывают цель. Совместимый `/me/notifications` также проверен. |
| Внешняя доставка | E2E проверяет конкурентный claim, lease, ошибку, backoff, исчерпание попыток, ручной retry, `noop`, отзыв доступа и безопасные состояния/метрики. SMTP не выполняется внутри учебной транзакции. |
| Email-настройка | По умолчанию выключена. Unit проверяет немедленное отражение выбора, блокировку повторной записи до ответа и rollback при ошибке; браузер включает и выключает настройку. |
| Административный экран | В браузере видны состояния доставки на обоих размерах; частный комментарий отсутствует. Retry требует ревизию, причину и аудит в API e2e. |
| Конкуренция | PR #8–9 устраняют временные P2034 в старых модулях; новый модуль использует тот же ограниченный принцип. Unit проверяет исчерпание и отсутствие повторов для прав, валидации, уникальности и настоящих пересечений. |

## Воспроизводимые команды

Из корня, с настроенными переменными тестовой среды:

```powershell
pnpm install --frozen-lockfile
pnpm run quality
pnpm --dir oge-tutor-backend run test:e2e
pnpm --dir oge-tutor-backend run test:migrations
pnpm --dir oge-tutor-app exec playwright test --grep 'real API'
pnpm --dir oge-tutor-backend run learning:operator rebuild-progress
pnpm --dir oge-tutor-backend run learning:operator deliver
```

Для e2e обязателен `E2E_DATABASE_URL` одноразовой базы с применёнными миграциями; для миграционной проверки — `DATABASE_URL` тестовой среды. Для production frontend build нужен корректный `VITE_API_BASE_URL`, `VITE_USE_MOCK=false`. Браузерные фикстуры/учётные данные задаются переменными из `.github/workflows/ci.yml`; это только disposable-аккаунты. На Windows нельзя запускать `prisma generate` одновременно с процессом, удерживающим DLL клиента: сначала остановить свой тестовый backend/e2e.

`prisma migrate reset` и demo seed не являются инструкцией обновления рабочей базы. Перед реальным обновлением нужен проверенный backup/restore БД **вместе с файлами**, тест миграции копии и план forward fix. После новых записей v2 простой возврат старого кода не гарантирует возврат данных.

- Нет VPS, серверного расписания бэкапов и production rollout.
- Блок 7, серии занятий и окончательное отключение v1 не реализовывались.
