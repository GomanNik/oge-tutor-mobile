# Блок 4: результаты локальной приёмки

Дата: 2026-10-25. Ветка: `codex/block4-lessons` поверх `codex/block3-courses` (PR #5). Проверки выполнялись на отдельных локальных PostgreSQL-базах `oge_tutor_block4_test`, `oge_tutor_block4_e2e_test`, `oge_tutor_block4_demo_test`; пользовательские контейнеры и их основная БД не обновлялись. Эти результаты **не** означают merge, зелёный CI нового PR или промышленное развёртывание.

| Критерий | Локальный результат |
|---|---|
| Миграции и обратная совместимость | Десять миграций развернулись на свежей БД. `test:migrations` прошёл пустую схему, legacy-данные, повторный deploy, backfill recovery, сохранность ID/сессий и FK-защиту снимков. `prisma validate` и `migrate diff` не выявили дрейфа. Основной сид создаёт v1-уроки со снимками и повторно запускается на одноразовой базе; демо-сид также повторяем. |
| Домен, права и HTTP | PostgreSQL e2e: 12/12. Новый сценарий покрывает группу из двух учеников, индивидуальную консультацию в той же группе, пересечение преподавателя и ученика через разные курсы, роли и другое пространство, приватность ответа ученика, идемпотентность, ревизии, завершение/посещаемость/исправление с аудитом, отмену, освобождение слота и гонку двух созданий. Все реально вызванные v2-ответы проверены по OpenAPI. |
| Backend и frontend | `pnpm run quality`: backend build/lint и 67/67 unit, frontend build/lint/typecheck и 40/40 unit. `pnpm run audit` прошёл; известный `GHSA-vfj7-8cjw-p6xm` остаётся в dev tooling без upstream patch. Vite сообщает предупреждение о чанке больше 500 kB, сборку это не блокирует. |
| Реальный браузер | На отдельных локальных backend/frontend новые Playwright-сценарии 2/2 прошли при 390 и 1365px: групповой курс, два зачисления, preview, создание урока, вид администратора и ученика, отсутствие чужого ученика/заметки, отсутствие горизонтального переполнения. Старые smoke для каталога и курсов: 3/3. CI browser-real-api job дополнен переменными для нового сценария. |
| Docker | Backend и frontend образы собраны локально под тегами `block4-local`, без обновления работающих контейнеров. |

Перед принятием PR нужны зелёные CI jobs на опубликованном коммите и независимая проверка изменений. Перед реальным запуском нужны backup/restore репрезентативной БД и файлов, сверка миграции с настоящими данными, план forward fix, наблюдаемость и расписание бэкапов. VPS пока нет; локальная сборка не подтверждает работу на сервере. Повторения, задания и прогресс остаются в следующих блоках.
