# Блок 5: работы, попытки, проверки, материалы и файлы

Дата реализации: 2026-10-25. Блок 5 принят по решению владельца: [PR #7](https://github.com/GomanNik/oge-tutor-mobile/pull/7) слит в `main` коммитом `33827dd`, CI финального коммита прошёл 7/7 jobs. Обновление действующих контейнеров выполняется отдельно. Прогресс, уведомления и повторяющиеся занятия относятся к следующим блокам.

## Граница и модель

Одна `Assignment` принадлежит одному курсу и версии программы этого курса. Она хранит выбранные `taskDefinitionIds` и снимок названий, кодов, максимумов и критериев задач. `AssignmentRecipient` фиксирует конкретное зачисление и собственный срок/статус. Выдача группе создаёт явные строки получателей; позднее зачисление ничего не добавляет автоматически. Дополнительная выдача требует отдельного действия и не меняет уже выданную работу.

`AssignmentSubmission` хранит попытку, текст, снимок условия на момент сдачи, дату и связи с файлами. Попытки не перезаписываются. `AssignmentReview` хранит решение (`accepted`/`rework`), критерии/баллы, комментарий, файлы и, для исправления, обязательную причину. Проверка сначала черновик; ученик видит только опубликованные версии. Исправление опубликованной проверки создаёт новую запись с возрастающим номером. Исторический автор, время и предыдущая редакция сохраняются. Результаты проверок блока 5 пока не вычисляют прогресс и не создают уведомления.

`LearningMaterial` привязан к опубликованной версии программы, опционально к задачам и одному источнику: HTTP(S)-ссылке либо файлу. Публикация `MaterialPublication` адресуется курсу и явным `MaterialPublicationRecipient`; занятие указывается опционально, но его участники должны включать каждого адресата. Отзыв публикации закрывает ученический доступ, архив материала отзывает все публикации. После первой публикации содержимое материала не меняется; новую редакцию нужно создать отдельно.

`FileResource.workspaceId` и `checksum` расширяют старую таблицу без изменения старых файлов. У каждой новой загрузки определены владелец, пространство, назначение, тип, размер и SHA-256. Связи с работой, попыткой, проверкой и материалом самостоятельны. Удаление уже связанного файла запрещено. Физические файлы не кладутся в JSON-ответы и не отправляются всем участникам группы.

## Состояния и инварианты

| Объект | Переход / ограничение |
|---|---|
| Работа | `draft → published → closed → archived`; черновик можно сразу архивировать. Содержание после публикации неизменно на уровне API и БД. Закрытую работу нельзя дополнять получателями или сдавать; ожидающие проверки попытки разрешено проверить, но для `rework` нужна открытая работа. |
| Получатель | `assigned → submitted → reviewed` либо `needs_revision → submitted`; до сдачи возможны `exempted` и `closed`. Персональный срок будущий, причина исключения/смены срока обязательна. Уже проверенный результат меняется только новой проверкой. |
| Попытка | Только последняя попытка может получить новую проверку. Предыдущие попытки, файлы и снимки неизменяемы. Номер попытки уникален внутри получателя. |
| Проверка | `draft → published`; публикация необратима. Новая версия проверки требует причины, а черновик у одной попытки может быть один. Баллы допускаются только по задачам опубликованной работы, не выше критериев и максимума. |
| Материал | Создание/правка до первой публикации; публикация выбранным активным зачислениям; отзыв конкретной публикации; архив всей записи с отзывом доступов. Дублирующая активная публикация одному получателю в том же контексте отклоняется. |
| Курс и зачисление | Нельзя завершить/приостановить связанные активные состояния без разрешения открытых работ; исторические записи сохраняются. |

Все доменные мутации работают в `Serializable` транзакции PostgreSQL с проверкой актуального членства и роли. `If-Match` сравнивает ревизию редактируемого ресурса; при несовпадении `412`, без заголовка `428`. Создание, публикация, сдача и публикация проверки требуют `Idempotency-Key` до 128 символов; запись ключа живёт 24 часа, повтор с иным телом даёт `409`. Операции пишут `WorkspaceAuditEvent`; аудиторские записи не содержат тело решения или файл.

## Права

| Действие | Администратор | Преподаватель | Ученик |
|---|---|---|---|
| Списки/карточки работ | Заголовки/получатели своего пространства | Только назначенные курсы | Только свои выданные работы и собственный получатель |
| Выдача и управление сроком | Курсы пространства | Назначенные курсы | Нет |
| Ответ и файлы ответа | Нет доступа к частному содержимому | Только назначенный курс | Только собственный ответ |
| Черновик/публикация проверки | Нет доступа к частному содержимому | Только назначенный курс | Только опубликованные собственные проверки |
| Библиотека материалов | Пространство | Собственные материалы и опубликованные в назначенных курсах | Только действующие адресные публикации при активных курсе и зачислении |
| Скачивание | Не обходит приватность ответа | По связанному курсу/собственному файлу | Собственный файл либо явно опубликованная работа, проверка или материал |

Проверка доступа повторяется при **каждом скачивании** и при запросе по прямому ID. При недоступном чужом объекте ответ `404`. Старая `/files/:id/download` не становится обходом для v2-файла. Исторические файлы с `workspaceId = NULL` доступны в v2 только через разрешённую связь, а в v1 остаются под прежними правами. Текущая роль выбирается `X-Active-Role`; наличие второй роли не расширяет возможности текущего запроса.

## API

Префикс всех маршрутов: `/api/v2/workspaces/{workspaceId}`. Swagger: `/api/docs`. Списки имеют `page`/`pageSize` (до 100), `total`, стабильный порядок и фильтры курса/статуса/поиска; материалы также фильтруются по версии и задаче. Мутации возвращают `{ item, changed, requestId }`, не полный снимок кабинета.

| Маршрут | Назначение |
|---|---|
| `GET/POST /assignments`, `GET/PATCH /assignments/{id}` | Список, создание черновика, карточка и правка до публикации. |
| `POST /assignments/{id}/publish`, `POST /assignments/{id}/recipients` | Первая выдача и отдельное добавление выбранных получателей. |
| `POST /assignments/{id}/close`, `POST /assignments/{id}/archive` | Закрытие/архивирование с причиной. |
| `GET /assignments/{id}/recipients`, `PATCH /assignments/{id}/recipients/{recipientId}` | Получатели, срок, освобождение и повторное открытие. |
| `GET/POST /assignment-recipients/{id}/submissions` | История попыток / новая попытка ученика. |
| `POST /submissions/{id}/reviews`, `PATCH /reviews/{id}`, `POST /reviews/{id}/publish` | Черновик, правка черновика, публикация результата. |
| `GET/POST /materials`, `GET/PATCH /materials/{id}` | Библиотека и черновик материала. |
| `POST /materials/{id}/publish`, `POST /materials/{id}/publications/{publicationId}/revoke`, `POST /materials/{id}/archive` | Адресная публикация, отзыв, архив. |
| `POST /files`, `GET /files/{id}/download`, `DELETE /files/{id}` | Потоковая загрузка, авторизованная выдача и удаление несвязанного файла. |

Невалидный DTO и неизвестные поля дают `400`; предметные ошибки `422`; конфликт состояния/повтора `409`; чужой объект `404`. `GET`-страницы не открывают другие попытки или черновики проверок ученику. Файл отдаётся с `nosniff`, приватным `no-store` и ограничительной CSP. При загрузке проверяются MIME, фактическая сигнатура/содержимое и лимит размера; потоковый приём не держит весь файл в памяти. Неудачная транзакция удаляет уже записанный физический файл.

## Совместимость и миграция

Миграция `20261025180000_assignments_materials` расширяет схему и переносит старые `Homework`, `HomeworkSubmission`, `MaterialAttachment` в v2-представление. Привязка идёт через созданные в блоке 3 `LegacyCourseMapping`; исходные ID и таблицы v1 не удаляются. Триггеры синхронизируют последующие записи старого кабинета, включая ответы, проверки и адресную доступность материала при изменении задания, темы материала или состава задач урока. Импорт помечается `legacy`, v2 отображает исторические данные без права их редактировать; старый кабинет остаётся местом записи для таких строк. Если старого автора проверки нельзя установить из v1-схемы, в импортированной проверке `reviewerUserId = NULL`, `source = legacy`; выдумывать автора нельзя.

До применения к работающей БД обязателен согласованный backup **БД и uploads**, restore на отдельной среде, сверка чисел/связей и окно отката. Одноразовый тест миграции проверяет свежую базу, базу с историческими ДЗ/ответом/проверкой/материалом, повторный deploy и защиту неизменяемой истории. Локальный тест не заменяет проверку на копии реальной базы пользователя. Контейнеры пользователя эта ветка не обновляет.

## Приёмка блока

1. `prisma migrate deploy`, `prisma migrate status`, `prisma migrate diff --exit-code`, `prisma validate`, `test:migrations` на одноразовых базах.
2. Backend build/lint/unit и PostgreSQL e2e всех блоков: группа, выборка получателей, приватность, файлы, повтор запроса, ревизии, попытки, проверка и исправление, публикация/отзыв материала, совместимость v1; реальные v2-ответы проверяются по OpenAPI.
3. Frontend build/lint/typecheck/unit и Playwright против реального API на мобильном и широком экране; преподаватель создаёт и проверяет, ученик видит лишь своё и сдаёт, материалы открываются только адресату.
4. Docker build обеих частей, аудит зависимостей и зелёный CI опубликованного PR. До merge это локальная готовность, не официальный выпуск.
5. Перед пилотом на VPS: backup/restore реальных файлов и БД, контроль миграции, наблюдаемость, расписание бэкапов. VPS пока нет; это **не** выполнено и не объявляется частью локальной приёмки.
