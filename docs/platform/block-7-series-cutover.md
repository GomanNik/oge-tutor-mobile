# Блок 7: серии занятий и завершение перехода на v2

Дата: 2026-10-26. База реализации: принятый `main` `559944e`, блоки 1–6. Ветка: `codex/block7-series-cutover`. Документ описывает реализованный контракт ветки, а не факт слияния или промышленного запуска. Результаты прогонов и оставшиеся ограничения фиксируются отдельно в [отчёте проверки](block-7-verification.md). Инструкция оператора: [переключение и восстановление](block-7-operations.md).

## Граница блока

1. Повторяющиеся индивидуальные и групповые занятия поверх существующих курсов, преподавателей, зачислений и правил доступа.
2. Обязательный предпросмотр всего пакета, атомарное применение, защита от устаревшей ревизии, повторного запроса и конкурентного изменения расписания.
3. Изменение будущего расписания без удаления истории; отдельное занятие может стать исключением.
4. Автоматическое продление ограниченного горизонта с проверкой актуальных полномочий и конфликтов.
5. Управляемое отключение v1, возможность продолжить перенесённые курсы, задания, материалы и аккаунты в v2.
6. Сверка данных, проверка файлов по байтам, восстановление БД и файлов с пользовательскими сценариями через восстановленный API.
7. Браузерные сценарии, OpenAPI, миграционные ограничения, CI и эксплуатационная документация.

Не входят: платежи, видеозвонки, родители, синхронизация внешних календарей, общешкольные каникулы, сложные RRULE с несколькими временами в день, восстановление исключения кнопкой, физическое удаление v1-таблиц, production rollout и обещание численного SLO. Исключаемые даты задаются явно для серии. Для нового учебного периода создаётся следующая серия.

## Модель серии

`LessonSeries` принадлежит одному `Course`; перенести существующую серию в другой курс нельзя. Предмет, экзамен, уровень и версия программы наследуются от курса. Новый каталог или вторая копия расписания не создаются.

| Поле | Контракт |
|---|---|
| `topic`, `note` | Общая тема и заметка будущих создаваемых занятий. |
| `format` | `individual` / `group`, с прежними ограничениями размера состава. |
| `startsAtLocal` | Строка `YYYY-MM-DDTHH:mm`, локальный календарный якорь правила. |
| `untilLocalDate` | Последний включаемый локальный день; период правила не больше 366 дней. |
| `timezone` | Именованный IANA-пояс, проверяемый Temporal. Сохраняется в каждом занятии. |
| `frequency` | `daily`, `weekly`, `monthly`. |
| `interval` | 1–12 единиц выбранной частоты. |
| `weekdays` | ISO-дни 1–7 для недельного правила; уникальные и отсортированные. |
| `monthDays` | Дни 1–31 для месячного правила; несуществующая дата пропускается, не сдвигается. |
| `excludedDates` | До 100 локальных дат без занятия; исключение применяется до преобразования пояса. |
| `durationMinutes` | 15–480 минут реальной продолжительности после преобразования начала в UTC. |
| `materializeDays` | 7–90 дней ограниченного горизонта, по умолчанию 45. |
| `dstDisambiguation` | `reject`, `earlier`, `later`: выбор для осеннего повторяющегося времени. |
| `teacherLinkIds` | 1–10 назначений преподавателей именно этого курса. |
| `participantEnrollmentIds` | 1–100 зачислений именно этого курса. |
| `revision` | Ревизия команды/состояния серии, используется в `If-Match`. |
| `generation` | Поколение правила; увеличивается при изменении будущего расписания. |
| `operatorUserId`, `operatorRole` | Последний подтвердивший человек и роль; worker не повышает их полномочия. |
| `nextRunAt`, `failures`, `lastErrorCode` | Ограниченное повторение фоновой работы и безопасный код ошибки. |
| `materializedThrough` | Проверенный горизонт, не обещание бесконечно готового расписания. |

`LessonSeriesTeacher` и `LessonSeriesParticipant` имеют составные FK `(seriesId, courseId)` и `(courseTeacherId/enrollmentId, courseId)`. Урок содержит `seriesId`, `seriesRevision` (поколение), `seriesOccurrenceKey` (исходная локальная дата) и `seriesException`. Уникальность тройки не даёт повторно создать один экземпляр поколения. CHECK запрещает частичную идентичность серии, отрицательные ревизии и недопустимые лимиты. Автор серии ссылается FK на пользователя. Используемые записи удалять нельзя.

## Календарная семантика

Раскрытие календарного правила выполняет `rrule` 2.8.1, преобразование локального времени в UTC выполняет `@js-temporal/polyfill` 0.5.1. Не используется прибавление 24 часов к UTC для сохранения локального времени. Первичные источники: [rrule: floating times](https://github.com/jkbrzt/rrule/blob/master/README.md), [Temporal API](https://github.com/js-temporal/temporal-polyfill/blob/main/index.d.ts).

- Один календарный экземпляр в день, с исходным временем якоря. Дни недели и месяца фильтруются выбранным правилом.
- Весеннее несуществующее время является ошибкой предпросмотра даже при `earlier`/`later`: незаметного переноса на час нет. Нужно изменить время или исключить дату.
- Осеннее двусмысленное время по умолчанию блокирует пакет. `earlier`/`later` выбирается человеком и сохраняется в правиле.
- Уведомления и занятость используют конкретные UTC-интервалы занятий. Конец равен началу плюс реальная длительность.
- Прошедшие начала не создаются задним числом; якорь может оставаться в прошлом при продлении действующего правила.
- Пакет содержит не больше 200 новых экземпляров; изменение не отменяет более 200 будущих экземпляров за раз. Более 1000 исторических экземпляров серии требуют следующей серии, а не скрытой обрезки выборки.

## Состояния и операции

| Операция | Поведение |
|---|---|
| Создать | Проверить правило, состав и все интервалы горизонта; создать серию и занятия одной транзакцией. Начало за текущим горизонтом допустимо: пока 0 занятий. |
| Изменить | Только будущее: отменить ещё не начавшиеся `planned/rescheduled`, кроме персональных исключений; создать заменяющие экземпляры нового поколения. Старые ID и отмены сохраняются. |
| Изменить при паузе | Изменить правило и отменить затронутое будущее; не создавать новые экземпляры до возобновления. |
| Приостановить | Остановить дальнейшее продление, оставить уже материализованные занятия. |
| Возобновить | Повторно проверить весь пакет и создать недостающий горизонт. |
| Материализовать | Проверить и дополнить текущий горизонт, не воскрешать отменённые экземпляры. Для паузы сначала требуется resume. |
| Отменить | Отменить будущие незавершённые экземпляры, включая будущие персональные исключения. Проведённое и прошедшее сохраняется. |
| Завершить worker | После последнего локального дня состояние `completed`; занятия и результаты не переписываются. |

`canceled` и `completed` терминальны: для продолжения создаётся новая серия. Изменение/перенос одного экземпляра выполняется прежним API уроков, требует причины и выставляет `seriesException=true`. Его исходный `seriesOccurrenceKey` сохраняется, поэтому изменение общего правила не создаёт второе занятие на исходную дату исключения. Проведённые экземпляры также исключены из пакетной замены. Исправление посещаемости остаётся отдельным аудируемым сценарием блока 4.

## Предпросмотр, конкуренция и права

Предпросмотр возвращает `operation`, `canApply`, полный `occurrences`, полный `cancelLessons` с ревизиями, `preservedCount`, `issues`, `through`, `previewToken`, `expiresAt`. Даже пустой пакет требует подтверждения. Ошибки периода курса/связей, DST, самопересечения и занятости блокируют весь пакет; частичного успеха нет.

Подписанный HMAC-SHA256 токен живёт 5 минут. В отпечаток входят нормализованное правило, человек, пространство, роль, ID и ревизия серии, причина, план и существующие ревизии занятий. Он не является самостоятельным разрешением: сервер заново проверяет активное членство, назначение курса, состав и все конфликты.

Применение использует Serializable-транзакцию с ограниченным повтором `P2034`, блокировку строки серии и детерминированно упорядоченные блокировки всех старых/новых преподавателей и учеников. После блокировок план пересчитывается. Чужое занятие между preview и apply даёт `409 stale_preview`; ни серия, ни половина её занятий не остаются. Начавшийся между preview и apply урок также не отменяется.

`Idempotency-Key` до 128 символов обязателен для мутаций серии. Ключ связан с человеком, пространством, ресурсом и операцией; хранение ответа 24 часа. Повтор того же тела возвращает прежний результат, другое тело с тем же ключом даёт `409 idempotency_conflict`. Актуальные права проверяются до возврата сохранённого ответа. `If-Match` обязателен для команды существующей серии: отсутствие `428`, несовпадение `412`.

Администратор управляет сериями своего пространства. Преподаватель управляет только доступным ему курсом с действующим назначением. Ученик не читает и не редактирует правила серии; он видит только свои конкретные занятия с прежним скрытием чужого состава. ID из другого пространства не раскрываются. Для безопасной отмены/паузы допускаются уже завершившиеся зачисления, но это не позволяет генерировать новые занятия по недействующим связям.

## Фоновое продление

`LessonSeriesWorker` проверяет очередь раз в минуту, по умолчанию до 10 due-серий за проход; явный предел запуска ограничен 50. Успешная серия планируется снова через 15 минут. Claim использует `FOR UPDATE SKIP LOCKED`; одинаковые экземпляры защищены уникальностью и транзакциями. Если в горизонте нет новых экземпляров, ревизия не увеличивается.

Ошибка приводит к безопасному `lastErrorCode`, backoff от 60 секунд с ограничением 1 час; после пяти последовательных неудач серия приостанавливается. Нужно устранить причину и выполнить подтверждённый resume. Worker использует последний подтверждённый человеческий контекст: отзыв роли/назначения не заменяется системным администратором. Завершение истёкшей серии оформляется системным аудитом без новых занятий.

Таймер выключен при `NODE_ENV=test`, `CLI_MODE=true` или `LESSON_SERIES_WORKER_ENABLED=false`. Одноразовый `series:operator materialize` вызывает тот же механизм, не запускает HTTP и посторонние таймеры. Создания и отмены занятий вызывают существующий транзакционный механизм адресных уведомлений; SMTP не вызывается внутри учебной транзакции.

## Фактический API

Для маршрутов пространства префикс `W=/api/v2/workspaces/:workspaceId`, Bearer и `X-Active-Role`. Списки имеют `page/pageSize`, фильтры `courseId/status`. Не возвращается полный bootstrap кабинета.

| Метод и путь | Назначение |
|---|---|
| `GET W/lesson-series` | Пагинированные серии доступных курсов. |
| `GET W/lesson-series/:id` | Одна серия с правилом и эксплуатационным состоянием. |
| `POST W/lesson-series/preview` | Предпросмотр создания без записи. |
| `POST W/lesson-series` | Создание по `SaveSeriesDto`, токену и ключу. |
| `POST W/lesson-series/:id/preview` | Предпросмотр изменения с `If-Match`. |
| `PATCH W/lesson-series/:id` | Будущее изменение с ревизией, причиной, токеном и ключом. |
| `POST W/lesson-series/:id/actions/preview` | Предпросмотр materialize/pause/resume/cancel. |
| `POST W/lesson-series/:id/actions` | Подтверждение действия. |
| `GET W/release-status` | Только администратор: сверка 11 групп инвариантов и количеств. Не запускает тяжёлое чтение файлов по HTTP. |
| `GET /api/v2/runtime` | Публичное состояние версии и режима v1 без персональных данных. |
| `POST /api/v2/auth/password-reset` | Нераскрывающий существование аккаунта запрос восстановления; SMTP/noop по текущей конфигурации. |
| `POST /api/v2/auth/access-token/verify` | Проверка одноразовой ссылки. |
| `POST /api/v2/auth/access-token/complete` | Одноразовая установка пароля и отзыв прежних сессий. |
| `POST /api/v2/me/password` | Текущий и новый пароль; атомарный отзыв всех сессий и неиспользованных токенов. |

DTO, тела и JSON-ответы описаны в `/api/docs` и `/api/docs-json`. Успешная мутация серии возвращает `item`, `createdCount`, `canceledCount`, `changed`, `requestId`. Смена пароля возвращает успешный ответ без новой сессии, после чего клиент открывает вход. Неверный текущий пароль даёт `422`, а не `401`, чтобы не уничтожать ещё действующую сессию. Пароли проверяются с учётом лимита bcrypt 72 UTF-8 байта. Гонка «старый пароль проверен до смены, сессия создана после» закрыта условной проверкой хеша при выдаче сессии.

## Завершение v1 без потери данных

`LEGACY_API_MODE=enabled|read_only|disabled`, по умолчанию enabled. Это глобальный переключатель развёртывания, не флаг отдельного курса. При read_only старые чтения и действия безопасности работают, учебные записи запрещены; импортированные сущности v2 пока тоже read-only. При disabled старые маршруты, включая login и скачивание файлов v1, отвечают `410`, а перенесённые сущности доступны для штатной записи v2. Признак `legacy` остаётся происхождением, отдельный `legacyReadOnly` описывает возможность изменения.

В disabled требуется `LEGACY_CUTOVER_CONFIRM=verified-backup-and-reconciliation`. Startup записывает `LegacyCutover('v2-authoritative')` в БД. После этого запуск enabled/read_only отклоняется: возврат одного env-флага не восстановит старые учебные записи из новых данных v2. Приложение убирает переход в старый кабинет; token URL, восстановление, профиль и смена пароля используют v2. Старые таблицы, файлы, снимки и миграции остаются.

Сверка проверяет отображения учеников, состав уроков, адресатов работ, файлы попыток, источники материалов, историю и снимки прогресса, адресатов уведомлений, незаменённые приглашения v1, актуальность проекций и ошибки продления серий. После отключения допустимые изменения v2 не требуют равенства текущего материала старому зеркалу. Завершённое через v2 занятие импортированного курса создаёт факт посещаемости, не вымышленный уровень освоения и не повторный перенос всей истории.

Файловая сверка потоково считает SHA-256, проверяет размер, realpath и нахождение в UPLOAD_DIR. Страницы по 100 файлов, без загрузки содержимого целиком в память. Отсутствующий checksum не объявляется успехом. Его осознанное первоначальное принятие возможно только отдельной командой в read_only с причиной и аудитом manifest; это не доказательство происхождения старых байтов. Известный несовпадающий checksum никогда не перезаписывается этой командой.

## Критерии приёмки

- Миграции работают на пустой и заполненной старой БД, повторный deploy безопасен, Prisma не имеет drift. Проверяются составные FK, лимиты, уникальность экземпляра, неполные nullable-идентичности, сохранение истории и барьер переключения.
- Unit покрывают календарь, DST обоих переходов, редкие месячные даты, исключения, интервалы, пределы, режимы v1, конфигурацию, барьер, файлы и операторские предохранители.
- PostgreSQL E2E покрывает preview/create/update/actions, повторы ключа, изменённое тело, устаревшую ревизию/preview, пересечение, конкурентные серии/worker, исключения, завершённую историю, отзыв прав, изоляцию ученика/пространства и OpenAPI.
- Cutover E2E сохраняет импортированные занятия, попытки и материалы; проверяет v1 `410`, v2 запись, восстановление/смену пароля, отзыв двух сессий и запрет конфигурационного отката.
- В браузере при 390 и 1365 px: полный preview, создание/изменение/пауза/отмена, восстановление аккаунта, профиль, смена пароля, администраторская сверка, преподаватель и ученик после отключения v1. Нет горизонтального переполнения; снимки просматриваются.
- Restore drill восстанавливает реальный PostgreSQL dump и файлы, отбраковывает повреждённую копию, затем через восстановленный API проверяет вход, материалы, приватные ответы, новую сдачу/проверку/прогресс и `410` старого API.
- CI, production сборки, линт, типы, аудит и Docker build выполнены. Известные предупреждения не выдаются за устранённые.
