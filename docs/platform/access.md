# Доступ, безопасность и жизненный цикл данных

Статус: целевая политика, **не описание уже действующих разрешений**. Решения требуют проверки с владельцем продукта и специалистом по обработке персональных данных до промышленного запуска. Домен — в [domain.md](domain.md).

## Принцип проверки

Для любой операции одновременно должны выполняться: (1) действительная сессия `User`; (2) активное членство/назначение роли в выбранном `Workspace` либо отдельный глобальный допуск к каталогу; (3) capability действия; (4) связь актора с **конкретным объектом**: курсом, зачислением, получателем ДЗ или опубликованным материалом; (5) допустимое состояние объекта. Одной роли `teacher`, `student` или UUID объекта недостаточно. По умолчанию отказ.

В таблице `А` — администратор текущего пространства, `П` — назначенный преподаватель курса, `У` — сам зачисленный ученик, `К` — администратор глобального каталога. «Свой» означает проверенную связь с ресурсом; «нет» — отсутствие штатного права, а не скрытую кнопку UI.

| Действие | А | П | У | К |
|---|---|---|---|---|
| Пригласить/блокировать членство в пространстве, назначить роль | да | только по делегированному праву на приглашение, без назначения роли | нет | нет |
| Создать/архивировать курс, назначить преподавателя | да | создать черновик при разрешении; свой курс в пределах прав | нет | нет |
| Зачислить/перевести/завершить участие | да | свои курсы при разрешении и с проверкой вместимости | запросить выход/вступление; не подтверждать самостоятельно | нет |
| Читать список учеников курса | да, минимум данных | свой курс, минимум данных | свой профиль; список других учеников по умолчанию скрыт | нет |
| Создать/перенести занятие, отметить посещаемость | да, операционные права | свои занятия/назначенные участники | просмотр своего приглашения/статуса; не оценка чужой посещаемости | нет |
| Создать/опубликовать ДЗ и проверить ответ | операционное управление; проверка только при отдельном праве | свой курс и свои получатели; соведущему по назначенному праву | сдать/просмотреть только своё | нет |
| Видеть прогресс | опубликованная операционная сводка своего пространства | своих зачислений; чужая сводка без чужих приватных заметок только по отдельному допуску | свои опубликованные результаты | нет |
| Видеть личную заметку преподавателя | нет по умолчанию; break-glass по процедуре | автор; другим преподавателям только явно общая заметка | нет | нет |
| Публиковать материал для курса | при управлении курсом | свой курс и подходящая версия программы | нет | только глобальную библиотеку |
| Скачать работу ученика | отдельное право на курс/проверку | преподаватель конкретного получателя/проверяющий | владелец своей сдачи | нет |
| Создать глобальную версию программы/правило оценки | нет без `catalog.manage` | нет | нет | да |
| Просмотреть аудит учебных действий | в своём пространстве, с маскировкой чувствительного | собственные действия и события своего курса по политике | история действий над своими результатами, не полный аудит | только аудит каталога |

Пользователь с несколькими ролями действует в выбранном контексте, но backend проверяет **набор разрешений**, а не только имя экрана. Высокорисковые возможности (`roles.manage`, `catalog.publish`, `audit.read`, `data.export`, `schedule.override`, `private-note.break-glass`) назначаются отдельно и аудируются.

## Поля и области видимости

- `User` и профиль: email/контакты видны только человеку и уполномоченным управляющим; групповому однокурснику они не выдаются. Администратор пространства не меняет глобальный аккаунт в других пространствах.
- `Enrollment`: учебная цель, договорённости и публичная обратная связь видны преподавателю своего курса, администратору в рамках полномочий и самому ученику, если поле опубликовано. Приватная заметка преподавателя — отдельное поле/ресурс с отдельным ACL, не часть общего DTO.
- `Course`: преподаватель видит назначенных участников; ученик видит имя курса, преподавателя и своё участие. Наличие иных учеников не означает доступ к их персональным данным.
- `Lesson`: ученик видит своё приглашение, время, ссылку/место и разрешённые материалы. Посещаемость других учеников и внутренний комментарий преподавателя не выдаются.
- `AssignmentRecipient`, `Submission`, `Review`: всегда индивидуальны. Групповая работа создаёт общую инструкцию, но не общий ответ. Ученику выдаются только его строки; преподаватель получает их в рамках своего курса.
- `ProgressEvent`: хранит исходную оценку, автора и видимость. В личном кабинете публикуются только явно опубликованные события; административный отчёт может агрегировать без чужих приватных комментариев.
- `Notification`: хранится на получателя; ссылка на удалённый или закрытый объект повторно проверяет доступ при открытии.
- `FileResource`: владелец файла не является единственным критерием скачивания. Проверяется действующая/исторически разрешённая публикация в курсе, персональное назначение или авторство сдачи.

## Истечение связи и отзыв доступа

При блокировке членства или отзыве роли запросы немедленно теряют соответствующие права; для чувствительных изменений сессии пользователя отзываются. Выход из курса прекращает доступ к будущим занятиям и неперсональным закрытым материалам. Свои прошлые сдачи и опубликованные результаты пользователь видит в личной истории по принятой политике хранения; это не даёт доступа к текущему составу или новым материалам группы. Преподаватель, снятый с курса, теряет доступ к будущим данным; законное сохранение доступа к историческим проверкам для передачи дела требует отдельного ограниченного разрешения.

Проверки выполняются при **каждом** чтении и скачивании, включая старую ссылку, прямой URL и фоновый экспорт. Кешированные ссылки на файлы краткоживущие либо проходят через backend. Публичный статический каталог загрузок запрещён.

## Файлы и вложения

Загрузка потоковая, с лимитом размера/количества/типов, проверкой содержимого и безопасным случайным ключом хранения; имя пользователя не используется как путь. Публикация отделена от загрузки. Для каждого файла фиксируются владелец, пространство, статус, checksum и ссылки использования. Проверяющий получает только файл назначенного ответа; однокурсники не получают ни файл, ни имя файла, ни факт конкретной оценки. Отзыв публикации закрывает скачивание сразу. Уборка сирот проверяет отсутствие ссылок и срок хранения, не удаляет файл на основании одного неудачного запроса.

Для локального одного узла допустим защищённый volume с бэкапом БД и файлов; перед несколькими backend требуется общее объектное хранилище. Сканирование вредоносного содержимого и политика типов/сроков хранения должны быть определены до открытия загрузки внешним пользователям; MIME от клиента не является доказательством типа. Содержимое файлов не попадает в общие логи.

## Аудит и персональные данные

Аудируются назначения ролей, приглашения, массовое зачисление/перевод, изменение состава урока после публикации, переопределение конфликта расписания, публикация/исправление оценок, доступ по исключительному праву, экспорт и запросы на удаление. Событие содержит актор, время, пространство, объект, действие, причину и `requestId`; не содержит пароль, токен, полный файл или секретную заметку. Правка аудита через пользовательский API запрещена; срок хранения и доступ устанавливаются отдельной политикой.

Обычное «удалить» означает завершить/архивировать связь. Полное удаление или обезличивание персональных данных проходит отдельный проверяемый процесс: установить принадлежность, оценить связанные результаты/обязательства хранения, подготовить экспорт при необходимости, отозвать доступ, применить согласованную политику к БД/файлам/резервным копиям и записать итог. Конкретные правовые сроки и основания **не устанавливаются этим документом** и должны быть согласованы перед реальным применением.

## Угрозы и обязательные проверки

| Угроза | Контроль и тест |
|---|---|
| Подмена `workspaceId`, `courseId`, `enrollmentId`, `recipientId` | Параметры сопоставляются с авторизованной связью; интеграционный тест каждого list/detail/mutation/file маршрута на чужой ID. |
| Перевод/приглашение создаёт дубль аккаунта или раскрывает его наличие | Нормализация идентификатора, безопасный ответ и подтверждение связывания; тест существующего пользователя в другом пространстве. |
| Бывший участник открывает сохранённую ссылку | Повторная проверка публикации/прав при скачивании; тест выхода/блокировки. |
| Соведущий видит лишние личные заметки | Отдельная проекция DTO и право; тест каждой роли и режима. |
| Злоупотребление массовыми действиями | Предпросмотр, ограничение размера, идемпотентность, аудит и подтверждение; тест частичных отказов. |
| Конкурентные запросы обходят вместимость/календарь | Транзакционные блокировки/ограничения и параллельные тесты с реальной PostgreSQL. |
| Компрометация сессии или приглашения | Срок действия, отзыв, rate limit, безопасное хранение хешей токенов, повторная проверка роли. |
| Утечка через экспорт, логи, бэкап или уведомление | Минимизация полей, ограничение доступа, шифрование внешней копии, тест редакции логов и приватности уведомлений. |

Перед публичным запуском нужны независимая проверка разрешений, инвентаризация персональных данных и политики хранения, восстановление из бэкапа, а также проверка зависимостей и конфигурации окружения. Эти проверки нельзя заменить только наличием unit-тестов.
