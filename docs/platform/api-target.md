# Проект API v2

Статус: **целевой контракт блоков 2–7; идентичность и администрирование блока 1 реализованы отдельно**. Точные работающие маршруты блока 1 описаны в [../api.md](../api.md), [спецификации блока](block-1-identity-admin.md) и Swagger `/api/docs`. Этот документ не следует использовать как фактический HTTP-контракт для ещё не реализованных предметов, курсов и групп.

## Общие правила

- JSON UTF-8; даты — ISO 8601 с UTC offset, хранение в UTC, исходный IANA timezone передаётся отдельно. ID непрозрачны. Номер экзаменационного задания — отображаемый атрибут, API-связь использует `taskDefinitionId`.
- Аутентификация: `Authorization: Bearer <token>` с серверной проверкой сессии. Активное пространство задаётся путём `/workspaces/{workspaceId}` либо явно выбранным контекстом для `/me`; роль и связь с ресурсом проверяются на каждый запрос.
- Списки по умолчанию ограничены; `limit` имеет серверный максимум, сортировка стабильна с ID как tie-breaker. Для журнала, уведомлений и истории предпочтителен opaque cursor; на небольших административных списках допустим `page/pageSize`. Ответ сообщает реально применённые фильтры и `nextCursor`/`hasMore`. `total` опционален там, где точный подсчёт дорог; UI не выводит ложное число из длины первой страницы.
- Тело каждого POST/PATCH строго валидируется, неизвестные поля отклоняются. Ошибки используют существующую форму `{ code, message, fieldErrors, requestId }`, дополненную безопасными `details` и `retryable` там, где нужно. Никаких приватных данных в диагностике чужого ID.
- Создание, публикация, массовое действие, перенос и сдача принимают `Idempotency-Key`. Повтор с тем же ключом и тем же телом возвращает тот же результат; тот же ключ с иным телом — ошибка. Срок хранения ключей ограничен и документирован.
- Изменяемые сущности имеют целочисленный `revision`/ETag. PATCH и state transition требуют `If-Match`; несоответствие — `412 precondition_failed`, без потери чужого изменения. Бизнес-конфликт — `409` с машиночитаемым кодом и только разрешёнными для актора деталями.
- Публичные действия входа/приглашения лимитируются. Создание и изменение возвращает конкретный ресурс/изменения и ссылки для refresh, а не весь кабинет. Серверные сводки вызываются отдельно.
- `DELETE` применяется только к неиспользованным черновикам/связям, для которых реально разрешено физическое удаление. Штатные завершения/архивирование — явные переходы состояния через POST/PATCH.

## Каталог и контекст

| Маршруты (после `/api/v2`) | Чтение/изменение | Право и смысл |
|---|---|---|
| `GET /me`, `GET /me/workspaces`, `POST /auth/logout` | Профиль, доступные пространства и роли, отзыв текущей сессии. | Сам пользователь. Вход/восстановление дополняют существующий безопасный поток, точные auth-маршруты выбираются при версии. |
| `GET /subjects`, `GET /programs`, `GET /programs/{id}/versions`, `GET /program-versions/{id}/tasks` | Пагинированный/кешируемый каталог с фильтрами `examType`, `subjectId`, `variant`, `period`, `status`. | Доступный опубликованный каталог; черновики только уполномоченным. |
| `POST /programs`, `POST /programs/{id}/versions`, `PATCH /program-versions/{id}`, `POST /program-versions/{id}/publish`, `POST /program-versions/{id}/archive` | Создание/публикация версии и её неизменяемость. | `catalog.manage`; локальные черновики ограничены своим пространством. Изменение использованной версии запрещено. |
| `GET /workspaces/{w}/overview`, `GET /workspaces/{w}/permissions` | Серверные счётчики и применимые права/флаги UI. | Контекстная роль; overview не раскрывает чужие личные данные. |
| `GET/POST /workspaces/{w}/members`, `PATCH /workspaces/{w}/members/{id}`, `POST .../roles`, `POST .../roles/{grantId}/revoke` | Членство и назначения. | Администратор с `members.manage`; отзыв роли сохраняет историю и не удаляет аккаунт. |

## Курсы, состав и преподаватели

| Маршруты | Назначение |
|---|---|
| `GET/POST /workspaces/{w}/courses`, `GET/PATCH /workspaces/{w}/courses/{id}` | Фильтры по программе, преподавателю, статусу, формату, периоду; создание черновика, изменение допустимых полей. |
| `POST /workspaces/{w}/courses/{id}/activate`, `/pause`, `/complete`, `/archive` | Проверяемые переходы с предпросмотром последствий. Завершение не стирает историю. |
| `GET/POST /workspaces/{w}/courses/{id}/teachers`, `PATCH /workspaces/{w}/courses/{id}/teachers/{linkId}` | Назначение ведущего, помощника или замены и ограниченных прав; нельзя снять последнего ведущего действующего курса. |
| `GET/POST /workspaces/{w}/courses/{id}/enrollments`, `GET/PATCH /workspaces/{w}/courses/{id}/enrollments/{eid}` | Состав, приглашение, активация, пауза, завершение участия. Уникальность в курсе и вместимость проверяются в транзакции. |
| `POST /workspaces/{w}/enrollment-batches/preview`, `POST /workspaces/{w}/enrollment-batches` | Предпросмотр и атомарное массовое зачисление до согласованного лимита; возвращает список применённых и конфликтных строк. Для больших пачек — отдельная асинхронная операция со статусом, без скрытой частичности. |
| `GET/POST /workspaces/{w}/cohorts`, `GET/PATCH /workspaces/{w}/cohorts/{id}`, `POST .../members` | Административный поток. Членство в потоке само по себе не зачисляет в курс. |

Пример минимального создания курса:

```json
{
  "programVersionId": "pv_123",
  "title": "Математика, группа А",
  "defaultFormat": "group",
  "capacity": 12,
  "startsOn": "2027-09-01",
  "endsOn": "2028-05-31",
  "timezone": "Asia/Omsk",
  "leadTeacherUserId": "usr_456"
}
```

`capacity=1` обязательно для `individual`; для группы сервер проверяет положительный предел и согласованный максимум пространства. ID и даты в примерах условные, не утверждённые форматами Prisma.

## Занятия и календарь

| Маршруты | Назначение |
|---|---|
| `GET /workspaces/{w}/lessons?from=&to=&courseId=&teacherId=&studentId=` | Календарь в явном диапазоне; сервер фильтрует по праву, не отдаёт чужой состав. |
| `POST /workspaces/{w}/lessons/preview` | Проверить участников, время, конфликты и последствия до создания; не резервирует время. |
| `POST /workspaces/{w}/lessons`, `GET/PATCH /workspaces/{w}/lessons/{id}` | Создать разовый урок, получить разрешённую деталь, изменить с `If-Match` и повторной проверкой конфликтов. |
| `POST /workspaces/{w}/lesson-series`, `PATCH /workspaces/{w}/lesson-series/{id}` | Правило повторения, горизонт будущих экземпляров, предпросмотр изменения серии; прошлые занятия не переписываются. |
| `POST /workspaces/{w}/lessons/{id}/cancel`, `/complete`, `/attendance-corrections` | Отмена/завершение/аудируемая корректировка. `complete` принимает посещаемость по участникам и предметные события только для нужных учеников. |

Пример занятия внутри группового курса для одного ученика:

```json
{
  "courseId": "course_123",
  "format": "individual",
  "startAt": "2027-10-20T12:00:00Z",
  "endAt": "2027-10-20T13:00:00Z",
  "timezone": "Asia/Omsk",
  "teacherLinkIds": ["ct_1"],
  "enrollmentIds": ["en_7"],
  "topic": "Разбор диагностики"
}
```

Состав урока передаётся явными `enrollmentIds` и проверяется на принадлежность курсу/активность. Для всей группы UI может выбрать всех активных, но запрос публикует конкретный снимок, а не неоднозначное `all=true`. Конфликт возвращает `calendar_conflict`, диапазон и безопасные идентификаторы **только доступных актору** собственных объектов; чужие названия скрываются.

## Работы, прогресс, материалы

| Маршруты | Назначение |
|---|---|
| `GET/POST /workspaces/{w}/assignments`, `GET/PATCH /workspaces/{w}/assignments/{id}` | Черновик и просмотр; фильтры по курсу, ученику, статусу и сроку. Задания принадлежат версии программы курса. |
| `POST /workspaces/{w}/assignments/{id}/publish`, `/close` | Публикация фиксирует ревизию инструкции и `recipientEnrollmentIds`; результат содержит число и ID получателей. |
| `GET/PATCH /workspaces/{w}/assignments/{id}/recipients/{rid}` | Разрешённый персональный срок/освобождение; только конкретный получатель и уполномоченный преподаватель. |
| `POST /workspaces/{w}/assignment-recipients/{rid}/submissions` | Сдать ответ/файл; доступ только ученику-получателю, идемпотентность попытки. |
| `POST /workspaces/{w}/submissions/{id}/reviews`, `POST /workspaces/{w}/reviews/{id}/publish` | Рецензия и публикация; исправление новой ревизией, не overwrite истории. |
| `GET /workspaces/{w}/enrollments/{eid}/progress`, `/progress/events` | Текущее состояние и cursor-история по заданиям; фильтры `taskDefinitionId`, источник, даты. |
| `POST /workspaces/{w}/enrollments/{eid}/progress/assessments` | Ручное событие с автором, основанием и видимостью. |
| `GET /workspaces/{w}/students/{id}/program-progress?programVersionId=` | Производная межкурсовая сводка с источниками, версией алгоритма и временем актуальности. |
| `GET/POST /workspaces/{w}/materials`, `GET/PATCH /workspaces/{w}/materials/{id}`, `POST .../{id}/publish` | Библиотека и назначение на курс/урок/получателя; фильтры по версии программы и заданию. |
| `POST /workspaces/{w}/files`, `GET /workspaces/{w}/files/{id}/download` | Потоковая загрузка и проверяемое скачивание; отдельная привязка файла к материалу/сдаче. |

`POST /assignments/{id}/publish` использует конкретный список `recipientEnrollmentIds`. После публикации новые получатели добавляются отдельным проверяемым действием; прежние попытки и оценки не пересоздаются. Для группового списка API преподавателя может вернуть агрегат `submittedCount/reviewedCount`, но ученический ответ не содержит строк однокурсников.

## Уведомления, аудит и экспорт

| Маршруты | Назначение |
|---|---|
| `GET /me/notifications`, `PATCH /me/notifications/{id}`, `POST /me/notifications/read-all` | Уведомления и статус конкретного получателя. Ссылка на ресурс проверяется отдельно. |
| `GET /workspaces/{w}/audit-events` | Только уполномоченному администратору; фильтры по актору, объекту, действию и времени, ограниченные/маскированные поля. |
| `POST /workspaces/{w}/exports`, `GET /workspaces/{w}/exports/{id}` | Асинхронный экспорт допустимого среза с аудитом, сроком жизни и защищённой выдачей файла. Не в первом выпуске, но граница API определена. |

## Формы ответов и ошибок

Деталь: `{ "item": { "id": "...", "revision": 3, ... } }`. Список: `{ "items": [...], "pageInfo": { "nextCursor": null, "hasMore": false }, "total": 12 }`; `total` опускается, если не вычислялся. Мутация: `{ "item": {...}, "changed": ["courses", "calendar"], "requestId": "..." }`. Предпросмотр ничего не меняет и возвращает `canApply`, `warnings`, `conflicts`, `affectedCount`, `previewToken` с коротким сроком для подтверждения массового действия. Сервер повторно проверяет условия при применении: preview не является бронью.

| HTTP | Машинный `code` | Смысл |
|---|---|---|
| 400 | `invalid_request` | DTO/формат поля; `fieldErrors` без лишних данных. |
| 401 | `unauthenticated` | Отсутствующая, истекшая или отозванная сессия. |
| 403 | `forbidden` | Нет права в выбранном пространстве; не раскрывает существование чужих объектов. |
| 404 | `not_found` | Объект отсутствует или скрыт политикой. |
| 409 | `capacity_conflict`, `calendar_conflict`, `invalid_state`, `idempotency_conflict` | Состояние/конкурентная бизнес-операция. |
| 412 | `revision_mismatch` | С момента открытия объект изменился; клиент предлагает обновить данные. |
| 422 | `domain_validation` | Данные формально верны, но нарушают правило программы/дат/состава. |
| 429 | `rate_limited` | Ограничение частоты с безопасным `Retry-After`. |

Каждый маршрут документирует request/response/error OpenAPI-схемами, способ пагинации и минимальное capability. Контракт-тест сравнивает серверный ответ со схемой; отдельные e2e-проверки доказывают изоляцию по пространству и по получателю. Старый `/bootstrap` и API v1 остаются только на период миграции клиентов; срок их выключения принимается отдельно.
